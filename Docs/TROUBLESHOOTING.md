## #1. Unity 에디터 첫 실행 크래시 + 드라이버 업데이트 후 블루스크린 (2026-11-12)

### 증상
1. Universal 3D 프로젝트를 처음 열 때 Unity가 꺼지고 Bug Reporter 창이 뜬다 (2회 재현).
2. GPU 드라이버를 업데이트한 뒤에는 Unity만 꺼지는 게 아니라 **PC 전체가 블루스크린**으로 재부팅됐다.

### 1단계: Unity 크래시 원인 (증거: `%LOCALAPPDATA%\Unity\Editor\Editor.log`)
- 크래시 스택이 전부 `atidxx64.dll`(AMD DirectX 11 사용자 모드 드라이버)의 `AmdDxGsaFreeCompiledShader` 안에 있었다.
- 드라이버 버전은 `26.20.12028.2`, 날짜 **2019-08-16**.
- 판단: Unity 6.3이 셰이더를 컴파일할 때 2019년 드라이버의 셰이더 컴파일러에서 오류가 났다.
- 조치: 복원 지점을 만든 뒤 AMD Adrenalin **26.5.2**를 설치했다 (공식 서명 확인함).

### 2단계: 업데이트 후 블루스크린 (오류 코드 0x7F, 인수 8 = Double Fault)
- 드라이버 설치 중 1회, Unity를 열 때 1회, V3를 삭제할 때 1회, 부팅 직후 1회. 총 4회 발생했다.
- WinDbg(cdb)로 미니덤프를 분석(`!analyze -v`)하니 오류 모듈이 매번 달랐다.
  - `ArtDrv.sys`(AhnLab V3 Lite 파일 필터), `wcifs.sys`, `luafv.sys`, `gameflt.sys`
  - 모두 파일 시스템 필터 드라이버였다.
- **잘못된 1차 판단**: 덤프에 찍힌 이름만 보고 V3 Lite를 원인으로 보고 제거했다. 제거 후에도 블루스크린이 계속됐다 (`luafv`/`gameflt`로 찍힘).

### 3단계: 타임라인 대조로 진짜 원인 확정 (증거: `C:\Windows\INF\setupapi.dev.log` + 블루스크린 이벤트 1001)

| 시각 | 사건 |
|---|---|
| 2026-09-13 23:27 | AMD 드라이버 26.5.2 (U0201039.INF) 설치 |
| 09-13 23:41~23:53 | 블루스크린 0x7F(8) 6회 |
| 09-13 23:55 | 드라이버 롤백 (DiRollbackDriver) |
| 09-14 ~ 11-12 | 블루스크린 0회 (약 2개월) |
| 2026-11-12 22:25 | 같은 26.5.2 설치 |
| 11-12 22:27~22:51 | 블루스크린 4회 |
| 11-12 22:56 | 드라이버 롤백 → 이후 블루스크린 없음 |

- 결론: **26.5.2 드라이버가 설치되어 있을 때만** 블루스크린이 난다. 덤프에 찍힌 필터 드라이버들은 커널 스택이 깨진 순간 마침 실행 중이었던 것으로 판단한다.
- 교훈: 덤프 하나에 찍힌 모듈 이름이 곧 원인은 아니다. **변경 이력과 발생 시각을 대조**해야 한다.

### 현재 상태
- 드라이버는 2019 버전으로 롤백했다. 시스템은 안정적이다. DX11로는 Unity가 크래시하지만 Vulkan으로는 열린다 (4단계 참고).
- V3 Lite는 제거했고 Windows Defender가 실시간 보호 중이다.
- 정리: 26.5.2 설치 파일, MEMORY.DMP, `C:\AMD` 설치 파일을 삭제했다 (`C:\AMD\DxCache`는 드라이버 캐시라서 유지).
- 복원 지점: "AMD driver install - before" (2026-11-12 21:52). V3 제거 이전 시점이다.

### 4단계: Vulkan으로 우회 (2026-11-12 23:09, 증거: `Editor.log`)
- 조치: 드라이버는 2019 버전 그대로 두고, Unity를 `-force-vulkan` 인수로 실행했다.
  `Unity.exe -projectPath C:\Dev\CivilTwin -force-vulkan`
- 판단 근거: 크래시는 DX11 드라이버 파일(`atidxx64.dll`) 안에서 났다. Vulkan은 다른 드라이버 파일(`amdvlk64.dll`)을 쓰므로 문제 코드를 지나가지 않는다.
- 결과 (로그로 확인한 것):
  - `Forcing GfxDevice: Vulkan`, 장치 "Radeon RX 570 Series", Vulkan API 1.1.0 (드라이버 지원 1.1.108)
  - `[Project] Loading completed in 51.865 seconds`
  - 셰이더 컴파일러(UnityShaderCompiler) 10개가 동작하는 동안 3분 이상 크래시 없음, 블루스크린 없음
  - 로그에 `Crash!!!`, `atidxx64` 문자열 없음
- 추가 확인: 씬 뷰가 정상으로 보인다 (개발자 육안 확인). Unity Hub에 `-force-vulkan`을 등록하고 Hub로 열어도 창 제목에 `<Vulkan>`이 표시되고 로그에 크래시가 없다.
- Play 모드: 빈 씬(SampleScene)이 정상 실행되고 정지된다 (2026-11-12 육안 + 로그 확인).
- **아직 검증 안 된 것**: 장시간 사용 안정성. (빌드는 2026-11-21 확인: `Builds\Windows\CivilTwin.exe -force-vulkan`으로 실행됨. DX11로 여는 다른 PC는 검증되지 않음)
- **실행 파일의 글상자 색 (2026-11-21):** 실행 파일에서만 화면 글상자가 회색으로 밝게 나왔다 (에디터는 짙음, 두 경우 모두 Windows가 찍은 실제 창 그림으로 비교). 실행 파일(선형 색 공간)에서만 글상자 색을 선형 값으로 바꿔 넘기는 `HudStyle.Ui`로 고쳤다. 원인은 출력 단계의 sRGB 변환으로 추정한다.
- 주의: Vulkan 드라이버도 2019년 버전(1.1.108)이다. 이후 렌더링 이상이 생기면 드라이버 버전을 먼저 의심한다.

### 부수 피해: 블루스크린 때 저장 중이던 파일 손상 (2026-11-12 23:12 발견)
- 증상: 로그에 `Unknown error occurred while loading 'Assets/Settings/UniversalRenderPipelineGlobalSettings.asset'`
- 증거: 이 파일의 25,579바이트가 **전부 0x00**이다. 수정 시각 22:31:42는 Unity 실행 중 블루스크린이 난 시각과 같다.
- 판단: 파일을 쓰는 도중 전원이 끊기듯 재부팅돼서 내용이 디스크에 기록되지 못했다.
- Unity의 자동 대응: `Assets/` 바로 아래에 `UniversalRenderPipelineGlobalSettings.asset`과 `DefaultVolumeProfile.asset`을 새로 만들었다 (23:09:57).
- 전수 검사: `Assets`, `ProjectSettings`, `Packages`, `UserSettings`에서 0으로 채워진 파일은 이 1개뿐이다.
- 정리 (2026-11-12 23:20경, Unity를 닫은 상태에서 수행):
  1. Unity를 저장하며 종료하자 `GraphicsSettings.asset`이 새 파일(guid `47aeb90f…`)을 가리키도록 갱신됐다.
  2. 0으로 채워진 파일과 그 `.meta`를 삭제했다.
  3. 새 파일을 `.meta`와 함께 `Assets/Settings/`로 옮겼다. Unity는 파일을 경로가 아니라 `.meta` 안의 guid로 찾기 때문에 참조가 유지된다.
  4. 새 설정의 `m_VolumeProfile`을 템플릿 원본 `Assets/Settings/DefaultVolumeProfile.asset`으로 되돌리고, 빈 대체 프로필은 삭제했다.
- 검증: `Unity.exe -batchmode -quit -force-vulkan`으로 프로젝트를 열었다. 종료코드 0, `Unknown error occurred while loading` 0건 (`Logs/verify-cleanup.log`).
- 한계: 손상 전 원본과 글자 단위로 같은지는 확인할 수 없다 (원본이 남아 있지 않음). Unity가 기본값으로 다시 만든 파일이다.
- 교훈: 블루스크린 뒤에는 그 시각에 수정된 파일을 검사한다. Git 커밋이 있었다면 바로 복구할 수 있었다 → 1-1에서 Git을 먼저 초기화한다.

## #2. 배치 모드에서 저장한 미리보기 이미지의 색이 틀림 (2026-11-12, **미해결**)

### 증상
- 테스트 `미리보기_이미지를_저장한다`가 지형을 RenderTexture에 그려 `Logs/terrain-preview.png`로 저장한다.
- 지형의 모양과 위치는 맞다 (정사각형 지형, 남동쪽에 언덕).
- 색이 틀리다. 배경을 하늘색 (0.60, 0.75, 0.90)으로 지정했는데 연두색으로 저장된다. 지형은 풀색이 아니라 옅은 민트색이다.

### 시도한 것 (모두 같은 결과)
1. 카메라 HDR 켬 → 지형에 등고선 같은 검은 줄무늬까지 생김
2. 카메라 HDR 끔, MSAA 끔 → 줄무늬는 사라졌으나 색은 여전히 틀림
3. 읽어오는 텍스처 형식을 RGB24 → RGBA32 로 변경 → 변화 없음

### 판단
- **원인은 확인하지 못했다.** 후보는 두 가지다: (a) 2019년 Vulkan 드라이버의 오프스크린 렌더링 문제, (b) 캡처 코드의 설정 문제.
- 일반 에디터 화면(씬 뷰, Play 모드)은 개발자가 눈으로 보고 정상이라고 확인했다. 그래서 화면 표시 자체의 문제일 가능성은 낮다고 보지만, 지형을 띄운 상태로는 아직 확인하지 않았다.

### 추가 확인 (2026-11-12, 개발자 화면 캡처)
- Play 모드의 Game 뷰에서는 **정상으로 보인다**: 파란 하늘, 풀색 지형, 언덕의 음영. 콘솔 오류 0, 경고 0.
- 따라서 문제 범위는 "배치 모드에서 RenderTexture에 그려 파일로 저장하는 경로"로 좁혀졌다. 화면 표시는 문제없다.
- 그 경로 안에서의 정확한 원인(드라이버인지 캡처 코드인지)은 여전히 미확인이다.

### 현재 대응
- 이 이미지는 모양 확인용으로만 쓴다. 색과 조명은 Unity 화면에서 직접 본다.
- 계산 검증(표고, 좌표, 삼각형)은 숫자 테스트로 하므로 이 문제의 영향을 받지 않는다.

## #1 관련: 남은 해결 방법 (예비)
1. **다른 드라이버 버전**: Vulkan에서 문제가 생길 때만 시도한다. 26.5.2가 아닌 Adrenalin(이전 버전 페이지)을 설치한다. 복원 지점 생성 → 클린 설치 → 블루스크린 여부 관찰.
2. (참고) D3D12는 Unity가 거부한다: Feature Level 12.0 < 12.1 필터.
3. (참고) 26.5.2 드라이버 패키지(`u0201039.inf`)가 Windows DriverStore에 아직 남아 있다. 현재 사용 중인 드라이버는 아니다. 삭제 여부는 미정.
